1. Problem Statement
Yang dirugikan:
Warga: insiden (kecelakaan, kebakaran, kerumunan berbahaya, tindak kriminal)
terlambat ditangani karena deteksi bergantung pada laporan manual.
Operator command center: harus memantau banyak layar kamera secara manual,
mudah lelah, dan insiden terlewat.
Petugas lapangan: menerima informasi lisan/tidak terstruktur (lokasi dan bukti tidak
jelas), sehingga respons lambat.
Pimpinan Pemda: tidak punya data insiden terstruktur untuk evaluasi dan
pengambilan keputusan.
Penyebab: rekaman CCTV dipakai terutama untuk forensik setelah kejadian, bukan untuk
deteksi dini; tidak ada pencatatan insiden dan tindak lanjut yang terpusat.
Pernyataan masalah: Pemda membutuhkan sistem yang mengubah aliran CCTV menjadi
event terstruktur, memberi peringatan dini ke operator, dan mencatat penanganan insiden
dari awal sampai selesai.

3. Goals dan Non-Goals
Goals
1. Menampilkan daftar kamera dan statusnya (online/offline) dalam satu dashboard.
2. Menghasilkan event deteksi terstruktur dari video (untuk MVP: data simulasi atau
video sampel [ASUMSI]).
3. Operator dapat memvalidasi event dan membuat insiden dengan alur status yang
jelas.
4. Seluruh tindakan pengguna tercatat dalam audit log.
5. Akses dibatasi berdasarkan peran (RBAC).
Non-Goals (MVP)
Pengenalan wajah (risiko hukum UU PDP; keputusan scope menunggu Open Question
2).
Streaming video langsung berskala besar di Vercel (tidak didukung platform).
Aplikasi mobile native.
Integrasi ke sistem eksternal (112, kepolisian) dan penindakan otomatis (tilang
elektronik).
Pelatihan model AI sendiri.

6. Functional Requirements (MVP)
FR-1 Login dan RBAC
Autentikasi email/username + kata sandi; kata sandi di-hash dengan Argon2.
Sesi memakai token JWT dengan masa berlaku terbatas.
Peran: admin, operator, petugas, pimpinan. Setiap endpoint memeriksa peran.
Login gagal berulang (5 kali) mengunci akun sementara. Durasi: lihat Open Question 8.
FR-2 Manajemen Kamera
Admin dapat membuat, mengubah, menonaktifkan kamera: nama, lokasi (lat/long,
alamat), sumber stream/video sampel, status.
Status kamera: online, offline, nonaktif. Status offline ditentukan dari heartbeat atau
kegagalan pembacaan sumber.
Operator dapat melihat daftar dan detail kamera (read-only).
FR-3 Event Deteksi
Sistem menyimpan event: kamera, jenis, waktu, skor kepercayaan, path snapshot/klip.
MVP: event dibuat oleh modul simulator atau pemrosesan video sampel [ASUMSI].
Event baru tampil ke operator tanpa reload halaman (SSE atau WebSocket).
Event dengan skor di bawah ambang batas tidak ditampilkan sebagai alert (nilai
ambang: Open Question 9).
FR-4 Validasi Event
Operator menandai event: valid atau false alarm (wajib memilih salah satu).PRD: CCTV Analitik untuk K eamanan K ota

Event valid dapat dikonversi menjadi insiden. Satu event hanya boleh terhubung ke
satu insiden.
FR-5 Manajemen Insiden
Insiden memiliki jenis, tingkat keparahan (rendah/sedang/tinggi), lokasi, deskripsi, dan
petugas yang ditugaskan.
Alur status: baru, ditugaskan, diterima, di lokasi, selesai, ditutup. Transisi di luar alur
ditolak.
Setiap perubahan status menyimpan waktu, pelaku, dan catatan.
FR-6 Dashboard
Menampilkan jumlah kamera online/offline, jumlah event hari ini, insiden terbuka, dan
rata-rata waktu respons.
Grafik insiden per jenis dan per hari (rentang yang dipilih pengguna).
Pimpinan hanya dapat melihat (tidak mengubah data).
FR-7 Audit Log
Mencatat login, perubahan data, validasi event, dan perubahan status insiden: pelaku,
aksi, objek, waktu, IP.
Log tidak dapat diubah atau dihapus dari aplikasi (insert-only). Masa simpan: Open
Question 7.
FR-8 Footer Aplikasi
Tampil di semua halaman, termasuk halaman login.
Berisi logo Pemda, logo Universitas Teknokrat Indonesia, dan teks: Copyright©2026 by
Dhara Piolita dan Dr. Erliyan Redy Susanto, M.Kom.
File logo resmi disediakan pemilik (lihat Open Question 10); jika gambar gagal dimuat,

Risiko utama dan mitigasi
1. Batas serverless Vercel membatasi real-time dan video: mitigasi dengan polling untuk
demo, video sampel berupa file statis, dan analitik berjalan terpisah dari Vercel.
2. Kompleksitas pipeline video di Rust: mitigasi dengan simulator event di MVP.
3. Risiko hukum data pribadi (wajah, plat nomor): mitigasi dengan mengeluarkan
pengenalan wajah dari MVP dan menetapkan masa simpan data.
4. Waktu pengerjaan: ruang lingkup MVP sengaja dipersempit pada manajemen kamera,
event, insiden, dan dashboard.
Validasi terhadap kebutuhan footer: logo dan teks Copyright adalah aset statis di
komponen layout yang dipakai semua halaman; tidak ada hambatan teknis pada Rust,
PostgreSQL, maupun Vercel.
